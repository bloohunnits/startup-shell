BookieBrawler

2022 – Present · Founder & Lead Engineer · bookiebrawler.com

LIVE

bookiebrawler.com, still running

My biggest project and my real education in running a business. BookieBrawler is a premium suite of sports betting tools. Positive EV, arbitrage, a parlay builder, bet tracking, and live alerts, all built on real-time odds from 20+ sportsbooks. I build and run the whole thing solo, and the backend streams about a million odds updates a day. The same models put my own account in the top 1% of NCAA basketball bettors on Pikkit.

2,000+registered users
$2Kpeak MRR
1M+odds updates / day
TOP 1%NCAAB on Pikkit

Tools alone weren’t going to be enough though. I kept seeing sharp bettors congregate on Discord and Twitter to talk plays, so I built that community into the product itself. Think OddsJam meets X. Bettors share plays in a live feed, follow sharps, and point to a public wins-and-losses record instead of cherry-picked screenshots. That feed is the main differentiator now, and nobody else in the space has it.

Plenty has gone wrong along the way. I was acquiring users while the product was still under development, and a lot of them churned because honestly, other apps were better at the time. Churn is a problem we still deal with, but the experience is genuinely good now and I sharpen it every week off session recordings of real users. Distribution was its own lesson. The 50+ articles and tutorials I wrote on betting math grew into an organic engine that outpaced paid acquisition, and a UGC creator campaign is up next since that’s how consumer apps grow these days. We’re positioned better than we’ve ever been.

CardCraft

the forge. every card generated

A trading-card forge I built to go deeper into machine learning than just calling APIs. I trained my own character-level LSTM on 17,000 RPG names, and it runs entirely in the browser with TensorFlow.js. The model generates the name, then GPT-4 writes the character’s stats and summary and produces matching card art.

Friday

A compliant AI coding agent harness for government software delivery

Government engineers are locked out of tools like Cursor and Claude Code. Compliance rules, data-handling policies, and audit requirements all say no. So the teams maintaining the most legacy code in the country are missing the biggest productivity jump software has ever seen. Friday is an agent harness built for that world instead of against it. It runs on Amazon Bedrock, keeps a human in the loop on every change, gates every action against per-project policy, and records everything it does for review. The thesis is simple. Streamline the SDLC, don’t shortcut it. In government the review process isn’t going away, and a tool that fights it will never be adopted.

RAIN

Retrieval-Augmented Incident Network

A retrieval-augmented chatbot built to cut incident resolution time for support engineers. It strips PII out of every question before anything touches a model, searches past incidents for similar cases, and drafts the troubleshooting guidance and the user-facing response, all on approved AI services.

question→ PII sanitizer→ search past incidents→ grounded answer

Here’s the part I love. I build them in tandem, using Friday, my own agent harness, to build RAIN. The RAIN proof of concept is the one that’s been demoed to stakeholders and is now awaiting approval. And while Bedrock approval is pending, I got basic coding agent tasks and the RAIN bot working sufficiently on developer hardware, an M1 with 32GB of RAM running a small optimized Qwen model. So I can prove the concept live in the meantime.
